לקרוא לפני שמתחילים

  • הגרש בשם המתחם. הכתיב הנכון הוא מתחם דפנה׳לה והתו באמצע הוא גרש עברי (U+05F3), לא אפוסטרוף רגיל. יש להעתיק את המחרוזת מהמסמך הזה ולא להקליד אותה, אחרת ייווצר כתיב רביעי.
  • עמוד הבית מקודד עברית כישויות HTML. חיפוש-והחלפה על המחרוזת "דפנהלה" בקוד המקור של עמוד הבית לא ימצא כלום. את הטקסט הגלוי יש לערוך דרך עורך העמודים, ואת ה-JSON-LD דרך הבלוק שבו הוא מוגדר.
  • גיבוי. לפני עריכת בלוקי ה-JSON-LD יש לשמור עותק של הקוד הקיים.
  • פריטים שממתינים לתשובת הלקוח מסומנים במסמך במסגרת צהובה. אין להטמיע אותם לפני קבלת התשובה. כל השאר מוכן לביצוע.
1

גבוהה

להחליף בכל המקומות הבאים ל־מתחם דפנה׳לה. סך הכול שמונה מקומות בטקסט גלוי, תיקון אחד בתבנית הפוטר ושני מקומות בנתונים המובנים.

בדיקה בסיום

חיפוש טקסטואלי בקוד המקור הגולמי אינו בדיקה אמינה כאן: עמוד הבית מקודד עברית כישויות HTML, וחלק מה-JSON-LD מקודד אותה כרצפי \u. לכן הבדיקה מתבצעת על ה-DOM המעובד ועל ה-JSON-LD אחרי פענוח. לפתוח כל עמוד בדפדפן, לרוקן קאש, ולהריץ בקונסול:

[document.body.innerText,
 ...[...document.querySelectorAll('script[type="application/ld+json"]')]
      .map(s => JSON.stringify(JSON.parse(s.textContent)))
].join(' ').match(/דפנ[^\s,.<]{0,4}/g)

התוצאה הנדרשת בכל אחד מהעמודים: רק המחרוזות דפנה׳לה ו-דפנה. כל הופעה של דפנהלה או דפנל'ה משמעותה שנותר מקום שלא תוקן.

2

נתונים מובנים בעמוד הבית

גבוהה

בעמוד הבית קיימים כיום שלושה בלוקי JSON-LD נפרדים. הבלוק של Yoast תקין ואין לגעת בו. שני הבלוקים הידניים דורשים טיפול.

2.1 להסיר את ישות ה-WebPage הכפולה

בבלוק הידני קיימת ישות WebPage עם המזהה https://klompus.co.il/#webpage, בנוסף לישות ש-Yoast כבר מייצר עבור אותו עמוד. יש למחוק את הישות הידנית הזו במלואה. הישות של Yoast נשארת.

2.3 להסיר את בלוק ה-FAQPage

בעמוד הבית קיים בלוק FAQPage נפרד, ללא מזהה. שתי סיבות להסיר אותו:

  • גוגל הסיר את התוצאה העשירה של FAQPage לחלוטין ב-7 במאי 2026, לכל סוגי האתרים ללא יוצא מן הכלל, ומחק את התיעוד שלה ביוני 2026. הסימון כבר לא מייצר שום תצוגה בתוצאות החיפוש, ולכן אין מה להפסיד. הכלל הישן שלפיו FAQ מוגבל לאתרי ממשל ובריאות אינו רלוונטי יותר.
  • FAQPage הוא תת-סוג של WebPage. בלוק כזה ללא מזהה יוצר ישות עמוד שנייה ואנונימית לאותו עמוד עצמו, וזו בדיוק הכפילות שאנחנו מנקים בסעיף 2.1.

תוכן השאלות והתשובות הגלוי בעמוד נשאר במקומו ללא שינוי. רק בלוק הקוד מוסר.

אם מעדיפים בכל זאת להשאיר את הבלוק, חובה לתקן בתוכו את שם המתחם (שורה 10 בטבלה בסעיף 1). אין להשאיר אותו ללא תיקון.

2.4 פירורי הלחם בעמוד הבית אינם תקינים

Yoast מייצר בעמוד הבית ישות BreadcrumbList עם פריט אחד בלבד, "Home". גוגל דורש לפחות שני פריטים בישות כזו, ולכן הסימון הזה אינו תקין וגוגל מתעלם ממנו. בעמוד התפריט ובעמוד הסיפור יש שני פריטים והם תקינים.

הפתרון הוא לבטל את ייצור פירורי הלחם בעמוד הבית בלבד:

add_filter( 'wpseo_schema_needs_breadcrumb', function ( $needs, $context ) {
    return is_front_page() ? false : $needs;
}, 10, 2 );

add_filter( 'wpseo_schema_webpage', function ( $data ) {
    if ( is_front_page() ) {
        unset( $data['breadcrumb'] );
    }
    return $data;
} );
שני הפילטרים נדרשים, לא רק הראשון. ביטול הישות לבדה משאיר בישות ה-WebPage הפניה "breadcrumb": {"@id": "…#breadcrumb"} אל ישות שכבר לא קיימת, וזו הפניה שבורה. הפילטר השני מוחק גם את ההפניה.
בעדיפות נמוכה יותר מנקודת הציון ומהמזהה הכפול, אבל זו הזדמנות טובה לטפל בזה תוך כדי, אם ממילא נוגעים בקוד התבנית לצורך סעיף 2.6.

2.5 ניקוי קישור הפייסבוק בהגדרות Yoast

הקישור שנשלח כיום מכיל שאריות פרמטרי מעקב. בממשק Yoast, תחת הגדרות ← ייצוג האתר ← פרופילים חברתיים, להחליף את כתובת הפייסבוק בכתובת הנקייה:

https://www.facebook.com/profile.php?id=100063627215979

באותו מסך מומלץ לעדכן את שם הארגון ל-מסעדת קלומפוס, כדי שיהיה זהה לשם שבישות המסעדה.

לא להוסיף כרגע קישור לפרופיל העסק בגוגל לתוך sameAs. קישור שיתוף מ-Maps, כתובת חיפוש וכתובת מבוססת Place ID אינם אותו דבר, וחלקם מכילים פרמטרים זמניים. נמסור את הכתובת היציבה בנפרד לאחר שנשלוף אותה מפרופיל העסק. אין להמציא אותה.

2.6 המלצת המשך: איחוד ישות העסק לישות אחת

גם אחרי התיקונים שלמעלה, האתר עדיין מתאר את העסק בשתי ישויות: #organization ש-Yoast מייצר, ו-#restaurant הידנית. זה לא שבור וגוגל מתמודד עם זה, אבל זה לא נקי. הפתרון המסודר הוא להפוך את ישות ה-Yoast עצמה למסעדה, ואז יש ישות עסק אחת בלבד באתר.

add_filter( 'wpseo_schema_organization', function ( $data ) {
    $data['@type']    = 'Restaurant';
    $data['telephone'] = '+972-72-2221243';
    $data['priceRange'] = '₪₪';
    $data['servesCuisine'] = [ 'Burgers', 'Meat', 'Grill' ];
    $data['address']  = [
        '@type'           => 'PostalAddress',
        'streetAddress'   => 'מתחם דפנה׳לה',
        'addressLocality' => 'קיבוץ דפנה',
        'addressRegion'   => 'הגליל העליון',
        'addressCountry'  => 'IL',
    ];
    $data['geo'] = [
        '@type'     => 'GeoCoordinates',
        'latitude'  => 33.2287142,
        'longitude' => 35.6407689,
    ];
    $data['openingHoursSpecification'] = [ [
        '@type'     => 'OpeningHoursSpecification',
        'dayOfWeek' => [ 'Monday','Tuesday','Wednesday','Thursday','Friday','Saturday' ],
        'opens'     => '12:00',
        'closes'    => '22:00',
    ] ];
    $data['hasMenu'] = [ '@id' => 'https://klompus.co.il/menu/#menu' ];
    return $data;
} );

אם מיישמים את זה, הבלוק הידני של המסעדה מסעיף 2.2 מוסר לגמרי, וכל ההפניות הקיימות של Yoast ממשיכות לעבוד כי המזהה #organization לא משתנה.

זו המלצה, לא דרישה. היא נוגעת בקוד התבנית ולכן מסוכנת יותר מעריכת בלוק JSON-LD. אם אין גישה נוחה לקוד התבנית, לבצע רק את סעיפים 2.1 עד 2.3 ואת 2.5, ולדלג על הסעיף הזה ועל 2.4. עיקר הנזק היום הוא נקודת הציון השגויה והמזהה הכפול בין העמודים, ושניהם נפתרים בלי הפילטר.
3

נתונים מובנים בעמוד התפריט

גבוהה

עמוד התפריט מגדיר כיום ישות Restaurant נוספת עם אותו מזהה בדיוק כמו זו שבעמוד הבית, אבל עם כתובת שונה ונקודת ציון שונה. זו הבעיה החמורה יותר בנתונים המובנים של האתר: גוגל מקבל שתי גרסאות סותרות של אותו עסק תחת אותו מזהה.

יש להחליף את כל הבלוק הידני בעמוד התפריט בקוד הבא. ישות המסעדה נמחקת מהעמוד הזה לחלוטין, ונשארת רק בעמוד הבית.

בקטע הקוד שהופיע במסמך המקורי הייתה סוגר מסולסל מיותרת בסוף. הקוד שלמעלה הוא הגרסה התקינה. יש להריץ את התוצאה ב-Rich Results Test של גוגל אחרי ההטמעה.

H2: חניה ונגישות בקלומפוס

H2: איפה נמצאת קלומפוס במתחם דפנה׳לה?

לאחר ההגעה למתחם דפנה׳לה יש לעקוב אחר השילוט לקלומפוס. המסעדה פועלת במבנה הקבוע במתחם, ומציעה ישיבה במקום וגם אפשרות להזמנת טייק אווי.

H2: שאלות נפוצות על ההגעה לקלומפוס

שבע שאלות, כל אחת כ-H3 והתשובה כטקסט רגיל.

H3: איפה נמצאת מסעדת קלומפוס?
קלומפוס נמצאת במתחם דפנה׳לה שבקיבוץ דפנה, בגליל העליון. בעמוד זה מופיעים קישורים לניווט ישיר למסעדה באמצעות Waze ו-Google Maps.
H3: האם קלומפוס נמצאת בגן הצפון?
לא. קלומפוס עברה ממתחם גן הצפון למתחם דפנה׳לה שבקיבוץ דפנה. בעמוד זה מופיעים קישורי הניווט המעודכנים למיקום הנוכחי של המסעדה.
H3: מהן שעות הפתיחה של קלומפוס?
קלומפוס פתוחה בימים שני עד שבת בשעות 12:00 עד 22:00. ביום ראשון המסעדה סגורה. בחגים ובמועדים מיוחדים מומלץ לבדוק אם פורסם עדכון לשעות הפעילות.
H3: האם יש חניה ליד קלומפוס?
כן. במתחם דפנה׳לה קיימת חניה למבקרים, ובסמוך למסעדה קיימת גם חניית נכים.
גם בתשובה הזו, אם הלקוח מאשר שהחניה חינמית, לכתוב "חניה חינם למבקרים".
H3: האם קלומפוס נגישה?
כן. הדרך אל המסעדה נגישה, ניתן להתנייד בה באמצעות כיסא גלגלים וקיימים בה שירותים נגישים. מידע נוסף מופיע בהצהרת הנגישות של קלומפוס.
H3: האם כדאי להזמין מקום מראש?
מומלץ להזמין מקום מראש, במיוחד בסופי שבוע ובשעות העומס. ניתן לבצע הזמנה ישירות דרך האתר.
H3: האם ניתן להזמין טייק אווי?
כן. ניתן לבצע הזמנת טייק אווי מראש ולאסוף אותה מקלומפוס במתחם דפנה׳לה.

H2: מתכננים להגיע לקלומפוס?

בואו ליהנות מהמבורגר טוב, בירה קרה וארוחה שכיף לעצור בשבילה.

מתחת לטקסט, חמישה כפתורים: לתפריט קלומפוס, להזמנת שולחן, להזמנת טייק אווי, ניווט ב-Waze, ניווט ב-Google Maps.

נתונים מובנים לעמוד החדש

אין ליצור ישות Restaurant נוספת בעמוד הזה, ואין להוסיף לו בלוק FAQPage נפרד, מאותן סיבות שבסעיף 2.3. Yoast ייצר עבורו WebPage ו-BreadcrumbList באופן אוטומטי, וזה מספיק.

השיפור היחיד המומלץ הוא לקשר את העמוד לישות המסעדה. השדה הנכון כאן הוא about, כי העמוד עוסק במסעדה אך אינו הישות עצמה. אם מיושם הפילטר מסעיף 2.6, המזהה יהיה #organization במקום #restaurant:

add_filter( 'wpseo_schema_webpage', function ( $data ) {
    if ( is_page( 'how-to-get' ) ) {
        $data['about'] = [ '@id' => 'https://klompus.co.il/#restaurant' ];
    }
    return $data;
} );
גם זה בעדיפות נמוכה. עמוד שעולה בלי השדה הזה תקין לחלוטין.

עמוד ארכיון ברירת מחדל

בינונית

מתוך שלושת עמודי ברירת המחדל שנבדקו, שניים כבר טופלו בעבר ואין בהם מה לעשות. נותר פריט אחד.

כתובתמצב שנמצא בבדיקהפעולה
/hello-world/מחזיר 404. הפוסט כבר נמחקאין פעולה
/author/yarin/מבצע הפניה 301 לעמוד הביתאין פעולה
/category/uncategorized/מחזיר 200, מוגדר index, follow, עם קנוניקל לעצמולהגדיר noindex

הפעולה המומלצת: בממשק Yoast, תחת הגדרות ← סוגי תוכן ← טקסונומיות ← קטגוריות, לכבות את הצגת ארכיון הקטגוריות בתוצאות החיפוש. זו פעולה אחת, הפיכה, ובלי נגיעה בקוד.

לא לנסות למחוק את הקטגוריה Uncategorized כברירת מחדל. וורדפרס מסרב למחוק את קטגוריית ברירת המחדל של האתר, והפעולה פשוט תיכשל בשקט. מחיקה אמיתית מחייבת קודם להגדיר קטגוריית ברירת מחדל אחרת, להעביר אליה פוסטים אם יש, ורק אז למחוק. זה מאמץ מיותר עבור התועלת, ולכן ההמלצה היא noindex.
אין צורך להסיר את הכתובת ממפת האתר. מפת האתר מכילה כיום רק את מפת העמודים, וארכיון הקטגוריות אינו מופיע בה כלל.
9

בדיקות סיום

גבוהה

לבצע אחרי ההטמעה, לפני החזרת המשימה.

הערה על הפילטרים: במסמך מופיעים כמה רישומים נפרדים ל-wpseo_schema_webpage. זה תקין ואינו התנגשות, וורדפרס מריץ את כולם בזה אחר זה. מי שמעדיף יכול לאחד אותם לפונקציה אחת עם כמה תנאים.

לרוקן קאש ו-CDN לפני הבדיקות, אחרת נבדקת גרסה ישנה.

  • בכל חמשת העמודים, סקריפט הבדיקה מסעיף 1 מחזיר רק דפנה׳לה ו-דפנה.
  • עמוד הבית, עמוד התפריט והעמוד החדש עוברים גם ב-Schema Markup Validator וגם ב-Rich Results Test של גוגל, ללא שגיאות וללא אזהרות חדשות.
  • בעמוד הבית קיימת ישות WebPage אחת בלבד. חיפוש #webpage מחזיר אפס תוצאות.
  • בעמוד התפריט אין יותר ישות Restaurant. חיפוש #restaurant בעמוד הזה מחזיר אפס תוצאות.
  • בכל האתר קיימת נקודת ציון אחת בלבד, והיא 33.2287142, 35.6407689.
  • אחרי הפענוח, הטלפון, הכתובת, השעות, נקודת הציון, כתובת התפריט וקישורי הרשתות זהים בכל העמודים שבהם הם מופיעים.
  • שני קישורי Tabit ושני קישורי הניווט נפתחים ומגיעים ליעד הנכון, גם ממכשיר נייד.
  • העמוד החדש מחזיר 200, מוגדר index, follow, יש לו קנוניקל לעצמו, והוא מופיע פעם אחת במפת האתר של Yoast.
  • אפס מופעים של #how בקישורי הניווט בכל העמודים.
  • העמוד החדש נבדק במסך נייד: פריסת RTL תקינה, הטבלה נגללת בתוך עצמה בלי לגרור את העמוד, המפה נטענת בלי קפיצת תוכן, והכפתורים לחיצים ונגישים גם במקלדת.
  • בסיום, לבקש סריקה מחדש של העמוד החדש ושל העמודים ששונו, דרך בדיקת כתובת URL ב-Search Console.
