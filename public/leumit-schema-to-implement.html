1.1 BreadcrumbList: שני ליקויים המבטלים את הסימון בכל האתר
קריטי2,191 עמודים

הליקוי הראשון. כל פריט במסלול פירורי הלחם משתמש במפתח "type" במקום "@type". בתקן JSON-LD רק "@type" מגדיר ישות, ולכן גוגל אינו מזהה את הפריטים כישויות ListItem. הליקוי קיים ב-2,191 העמודים הנושאים פירורי לחם, כלומר בכל עמוד באתר שאינו עמוד בית, בארבע השפות.

הליקוי השני. סדר הפריטים הפוך. מיקום 1 הוא העמוד הנוכחי, והמיקום האחרון הוא עמוד הבית. גוגל מחייב שמיקום 1 יסמן את תחילת המסלול.

הבהרה. לאחר היפוך הסדר, העמוד הנוכחי הופך לפריט האחרון, ובפריט האחרון השדה item אינו נדרש. לשון התיעוד של גוגל: "If the breadcrumb is the last item in the breadcrumb trail, item is not required." אין להוסיף item לעמוד הנוכחי.

ממצא נלווה. ב-83 עמודים מופיע אותו שם פעמיים באותו מסלול. יש לוודא שהשם נלקח משם הצומת עצמו ולא מכותרת האב.

איפה ב-Umbraco. תבנית ה-Master, לפני סגירת &lt;/head&gt;. מומלץ להוציא ל-Partial ייעודי, למשל ~/Views/Partials/Schema/BreadcrumbList.cshtml, ולקרוא לו מכל עמוד שאינו שורש האתר. Model.AncestorsOrSelf() מחזיר מהעמוד הנוכחי כלפי מעלה, ולכן .Reverse() מייצר את הסדר הנדרש.
@* ~/Views/Partials/Schema/BreadcrumbList.cshtml
   Renders BreadcrumbList for every page EXCEPT the site root.
   Fixes all three live defects at once: "@type" instead of "type",
   root-first ordering, and the last item correctly omitting "item". *@
@using System.Text.Json
@using System.Text.Encodings.Web
@{
    // AncestorsOrSelf() returns current -> root, so Reverse() gives root -> current.
    var trail = Model.AncestorsOrSelf().Reverse().ToList();

    // Google requires at least TWO ListItems. The homepage alone is not a valid trail.
    if (trail.Count >= 2)
    {
        var items = trail.Select((node, i) => {
            var li = new Dictionary<string, object> {
                { "@type",    "ListItem" },
                { "position", i + 1 },
                { "name",     node.Name }
            };
            // "item" on every node EXCEPT the last (Google: optional on the final item)
            if (i < trail.Count - 1) {
                li["item"] = node.Url(mode: UrlMode.Absolute);
            }
            return li;
        }).ToList();

        var graph = new Dictionary<string, object> {
            { "@context",        "https://schema.org" },
            { "@type",           "BreadcrumbList" },
            { "itemListElement", items }
        };

        var json = JsonSerializer.Serialize(graph);
        <script type="application/ld+json">@Html.Raw(json)</script>
    }
}

1.2 Organization: להגביל לעמודי הבית בלבד
גבוה2,195 ← 4

המצב היום. סכימת Organization מוזרקת ב-2,195 עמודים, כלומר בכל עמוד באתר. לפי התיעוד של גוגל סכימת הזהות של הארגון שייכת לעמוד הבית: "Add the markup to your home page".

מה לעשות. להתנות את ההזרקה בשורש האתר. לאתר ארבעה עמודי בית, אחד לכל שפה, והסכימה תישאר בארבעתם.

איפה ב-Umbraco. בתבנית ה-Master לעטוף את הקריאה בתנאי @if (Model.Id == Model.Root().Id) { ... }, ולהעביר את הבלוק ל-~/Views/Partials/Schema/HomepageGraph.cshtml.
1.3 הלוגו אינו עומד בדרישת המידות של גוגל
גבוהנכס מדיה

המצב היום. הלוגו שבסכימה הוא 36467_113985_leumit_website_bnrs_logo_208x52_05.png, ומידותיו בפועל 208 על 52 פיקסלים. דרישת גוגל ל-Organization מפורשת: "The image must be 112x112px, at minimum". גובה 52 פיקסלים נכשל בדרישה.

מה לעשות. להעלות נכס לוגו בגובה וברוחב 112 פיקסלים לפחות, מומלץ ריבועי על רקע לבן. מתיחה של הנכס הקיים אינה פתרון: מקור בגובה 52 פיקסלים יתקבל מטושטש.

איפה ב-Umbraco. Media, העלאת הקובץ, ואז Media Picker במסמך עמוד הבית. שכבת ImageSharp מאפשרת הגשה במידות מבוקשות באמצעות ?width=&amp;height=, אך היא אינה מייצרת מידע שאינו קיים בנכס המקור.
1.4 הסרת בלוק סכימה מת מהתבנית
בינוני2,195 עמודים

המצב היום. בכל עמוד באתר נשלח בלוק WebSite הנמצא בתוך הערת HTML. הבלוק אינו נכנס ל-DOM ואינו נקרא על ידי גוגל, אך הוא נשלח ברשת בכל בקשה. בעמודי הבית קיים בנוסף עותק חי, ולכן WebSite פעיל בארבעה עמודים בלבד.

מה לעשות. למחוק את הבלוק המוער. קוד מושבת שנשאר בהערה מסתיר את המצב האמיתי מכל בדיקה המסתמכת על קוד המקור, ומקשה על תחזוקה.

בשתי האפשרויות מספר הצמתים יורד משלושה לשניים, משום ש-Organization ו-MedicalOrganization מתארים את אותו גוף. השארתם כשני צמתים נפרדים תיוותר תקפה מבחינת גוגל, אך שני צמתים בעלי אותו שם, אותה כתובת, אותו לוגו ואותו טלפון מתארים שני ארגונים שונים. השדה parentOrganization נועד ליחסי חברה ובת אמיתיים, ולאומית היא ישות אחת.

2.1 VideoObject: 46 סרטונים ב-36 עמודים, ללא סימון כלל
תוצאה עשירה בגוגל36 עמודים

המצב היום. באתר משובצים 46 סרטוני יוטיוב ייחודיים ב-36 עמודים, בארבע השפות. אף אחד מהם אינו נושא סימון VideoObject. זו הסכימה בעלת הערך הגבוה ביותר מבין אלו שניתן להטמיע כעת, משום ש-Video הוא אחד מסוגי התוצאות העשירות שגוגל עדיין תומך בהם.
