7. הגדרת עמודי הבוגרים כ-ProfilePageדחוף◀

19 עמודי הבוגרים מסומנים כ-WebPage. נדרש סוג ProfilePage.

מדוע זה משנה: לסוג Person אין תוצאה עשירה עצמאית בגוגל. המשטח היחיד שבו גוגל צורכת אותו הוא כ-mainEntity של עמוד מסוג ProfilePage, שגוגל מגדירה במפורש כמתאים ל"עמוד עובד באתר של חברה". כל עוד סוג העמוד הוא WebPage, נתוני הבוגר קיימים בקוד אך אינם ניתנים לשימוש על ידי גוגל.

איפה מיישמים: בקובץ functions.php של תבנית הבת, או בתוסף פונקציונליות של האתר. לא נדרש שינוי בתוכן העמודים.

add_filter( 'wpseo_schema_webpage', function ( $data ) {
    if ( is_singular( 'graduate' ) ) {
        $data['@type'] = 'ProfilePage';
    }
    return $data;
} );
הפעולה הנדרשת: להוסיף את הקוד שלמעלה. לאחר מכן, בקוד המקור של עמוד בוגר כלשהו, הצומת שהיה "@type": "WebPage" יופיע כ-"@type": "ProfilePage". אין לגעת בשדה mainEntity.
8. תיקון פירורי הלחם בעמוד הביתדחוף◀

בעמוד הבית של האקדמיה צומת BreadcrumbList מכיל פריט אחד בלבד:

"@type": "BreadcrumbList",
"@id": "https://experis.co.il/academy/#breadcrumb",
"itemListElement": [
  { "@type": "ListItem", "position": 1, "name": "דף הבית" }
]
לפי מפרט גוגל, BreadcrumbList מחייב לפחות שני פריטים. רשימה בת פריט אחד אינה סימון תקין, ולכן הסימון בעמוד הבית נפסל.

איפה מיישמים: אותו קובץ functions.php. נדרשים שני המסננים יחד.

add_filter( 'wpseo_schema_needs_breadcrumb', function ( $needs_breadcrumb ) {
    return is_front_page() ? false : $needs_breadcrumb;
} );

add_filter( 'wpseo_schema_webpage', function ( $data ) {
    if ( is_front_page() ) {
        unset( $data['breadcrumb'] );
    }
    return $data;
} );
שני המסננים חובה, לא אחד. המסנן הראשון לבדו מסיר את צומת פירורי הלחם אך משאיר בצומת WebPage הפניה יתומה "breadcrumb": {"@id": "…#breadcrumb"} שמצביעה לצומת שכבר אינו קיים. המסנן השני מסיר גם את ההפניה.
הפעולה הנדרשת: להוסיף את שני המסננים. לאחר מכן בקוד המקור של עמוד הבית לא יופיע צומת BreadcrumbList כלל, וגם לא המפתח breadcrumb בתוך צומת ה-WebPage.
