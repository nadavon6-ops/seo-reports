הוראות תיקון למפתח — לפי סדר עדיפות

תיקון 1 — "type" → "@type" קריטי

בכל מקום שמייצר JSON-LD — להחליף "type" ב-"@type".

זה משפיע על: FAQPage (Question, Answer), BreadcrumbList (ListItem).

הערה: ב-SQATEST.html ה-FAQPage כבר משתמש ב-"@type" — אז כנראה יש נתיב קוד שונה בפרודקשן. יש לאתר את שורת הקוד שמייצרת את ה-JSON.

// C# / Razor — חפש את השורה הזו: new { type = "Question", name = q.Name, ... } // והחלף ב: new { @type = "Question", name = q.Name, ... } // או: new Dictionary<string,object> { {"@type", "Question"}, ... }

תיקון 2 — דיכוי schema כש-mainEntity ריק קריטי

הוספת תנאי בתבנית: אם אין פריטי שאלה-תשובה → לא להזריק את ה-FAQPage schema.

@if (Model.FaqItems != null && Model.FaqItems.Any()) { <script type="application/ld+json"> // FAQPage schema here </script> }

זה פותר את 4 הדפים הריקים ומבטיח שלא יתווספו דפים ריקים בעתיד.

תיקון 3 — סדר BreadcrumbList גבוה

להפוך את סדר הפריטים: דף הבית = position 1, דף נוכחי = position אחרון.

הפריט האחרון (דף נוכחי) — רק name, בלי item (URL).

תיקון 4 — בדיקת localhost URLs גבוה

ב-SQATEST.html כל ה-URLs מצביעים ל-https://localhost:44357.

יש לוודא שהפרודקשן מחליף אוטומטית ל-https://www.leumit.co.il.

בדקנו דפים חיים — ה-URLs מצביעים לדומיין הנכון. כנראה מוחלף אוטומטית.

תיקון 5 — הסרת "name" מ-FAQPage (אופציונלי) נמוך

השדה "name" ב-FAQPage לא נתמך רשמית ע"י גוגל, אבל הוא לא שובר כלום. אפשר להסיר כדי לנקות את הקוד.
