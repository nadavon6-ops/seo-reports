באג קריטי — "type" במקום "@type" ברמת Question ו-Answer

תצפית (עובדה): ה-wrapper של FAQPage משתמש ב-"@type" בכל 83 הדפים — גם בפרודקשן וגם בבדיקה. הבאג הוא רק ברמת ה-Question וה-Answer.
הסבר סביר (מסקנה, לא עובדה מוכחת): כנראה ש-"@type":"FAQPage" כתוב ישירות בתבנית (hardcoded), בעוד שפריטי Question/Answer נוצרים דינמית ע"י C# serialization. ב-C#, anonymous objects לא יכולים להכיל @ בשם property ללא טיפול מיוחד — מה שגורם ל-"type" במקום "@type".
למה ב-SQATEST.html זה תקין? יתכן שקובץ הבדיקה נוצר בנתיב קוד שונה, או שהמפתח ערך אותו ידנית. בלי גישה לקוד המקור של ה-C# — אי אפשר לקבוע בוודאות.
4 דפים עם mainEntity ריק לא נספרים בבדיקת prefix — אין להם פריטי Question/Answer לבדוק. לכן 79 ולא 83.

הוראות תיקון למפתח

תיקון 1 — "type" → "@type" ברמת Question ו-Answer קריטי

ה-FAQPage עצמו כבר משתמש ב-"@type" — תקין. הבאג הוא רק ברמת Question/Answer.

// C# — הבעיה הסבירה: new { type = "Question", name = q.Name, acceptedAnswer = new { type = "Answer", text = q.Answer } } // C# — הפתרון: new Dictionary<string,object> { {"@type", "Question"}, {"name", q.Name}, {"acceptedAnswer", new Dictionary<string,object> { {"@type", "Answer"}, {"text", q.Answer} }} }

תיקון 2 — דיכוי schema כש-mainEntity ריק קריטי

@if (Model.FaqItems != null && Model.FaqItems.Any()) { <script type="application/ld+json">...</script> }

תיקון 3 — BreadcrumbList: סדר + "@type" גבוה

להפוך את סדר הפריטים (דף הבית = 1) + להחליף "type" ב-"@type" + פריט אחרון ללא URL.

תיקון 4 — localhost URLs (לבדוק) נמוך

ב-SQATEST.html כל ה-URLs מצביעים ל-localhost:44357. בדפים החיים — ה-URLs מצביעים ל-www.leumit.co.il. כנראה מוחלף אוטומטית, אבל כדאי לוודא.
