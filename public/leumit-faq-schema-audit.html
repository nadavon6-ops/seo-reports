באג #1: "type": "Question" במקום "@type": "Question"

ה-FAQ schema בדף הזה משתמש ב-"type" ללא @. Google לא מזהה את הפריטים כ-Question/Answer — כל ה-FAQ schema שבור.

// ❌ מה שנמצא בדף: {"type": "Question", "name": "מחוז דרום"} // ✅ מה שצריך להיות: {"@type": "Question", "name": "מחוז דרום", "acceptedAnswer": {"@type": "Answer", "text": "..."}}
באג #2: חסר acceptedAnswer על כל Question

לפי מפרט Google, כל Question חייב להכיל acceptedAnswer מסוג Answer. בדף הזה, ל-Question items אין acceptedAnswer כלל.

// ❌ מה שנמצא: {"type": "Question", "name": "מחוז דרום"} // ✅ מה שנדרש: {"@type": "Question", "name": "שאלה כאן?", "acceptedAnswer": {"@type": "Answer", "text": "תשובה כאן"}}
באג #3: תוכן שאינו FAQ — מחוזות גיאוגרפיים כ"שאלות"

ה-"שאלות" בדף הן שמות מחוזות: "מחוז דרום", "מחוז ירושלים", "מחוז מרכז", "מחוז צפון". אלה לא שאלות אמיתיות.

⚠ Google מזהיר במפורש: "If your page has content that is not formatted as a question and answer, don't use FAQPage." — סיכון ל-Manual Action שמסיר Rich Results מכל האתר.

באג #4: BreadcrumbList — סדר הפוך + "type"

עמוד הבית צריך להיות position 1, הדף הנוכחי אחרון. כאן הסדר הפוך.

// ❌ מה שנמצא (הפוך + type שגוי): [ {"type":"ListItem","position":1,"name":"פפילומה (HPV)"}, {"type":"ListItem","position":2,"name":"שתהיו בריאים","item":"https://...leumit.co.il/diseases/"}, {"type":"ListItem","position":3,"name":"עמוד הבית","item":"https://...leumit.co.il/"} ] // ✅ מה שצריך (סדר נכון + @type): [ {"@type":"ListItem","position":1,"name":"עמוד הבית","item":"https://www.leumit.co.il/"}, {"@type":"ListItem","position":2,"name":"שתהיו בריאים","item":"https://www.leumit.co.il/diseases/"}, {"@type":"ListItem","position":3,"name":"פפילומה (HPV)"} ]

✓ FAQPage Schema — תקין

משתמש ב-"@type" בצורה נכונה, מבנה Question → acceptedAnswer → Answer תקין, mainEntity הוא מערך.

{"@context":"https://schema.org","@type":"FAQPage","name":"FFFF", "mainEntity":[{"@type":"Question","name":"JJJJ", "acceptedAnswer":{"@type":"Answer","text":"HHHH"}}]}

⚠ שימו לב: "name":"FFFF" מיותר — Google מתעלם מ-name ב-FAQPage. נמוך

BreadcrumbList: אותם באגים + כתובות localhost

כל ה-URLs מפנים ל-https://localhost:44357. בפרודקשן הכתובת מוחלפת ל-https://www.leumit.co.il (אומת).

Breadcrumb עדיין משתמש ב-"type" במקום "@type", וסדר positions הפוך.

ממצא מפתח: שני מסלולי קוד שונים

ה-FAQ component ב-SQATEST.html משתמש ב-"@type" (תקין), אבל הדף החי של פפילומה משתמש ב-"type" (שבור). זה מצביע על שני code paths שונים לרנדור JSON-LD.

רכיב SQATEST.html דף פפילומה (חי)
CSS class class="faq" class="faq _qAndA" (PregnancyQuestionsAnswers)
@type ב-JSON-LD ✓ "@type" — תקין ✗ "type" — שבור
acceptedAnswer ✓ קיים ✗ חסר
תוכן שאלה ותשובה (placeholder) מחוזות גיאוגרפיים (לא FAQ)

המפתח צריך לבדוק את שתי התבניות ב-Umbraco: גם את רכיב ה-faq (שמייצר FAQPage) וגם את רכיב ה-PregnancyQuestionsAnswers (שמייצר תוכן שגוי).

באג site-wide: BreadcrumbList

כל הדפים שנבדקו (חוץ מדף הבית) מכילים BreadcrumbList עם שתי בעיות זהות:

בעיה 1: "type" במקום "@type"

JSON-LD מחייב "@type" עם הסימן @. ללא @, Google לא מזהה את הפריטים כ-ListItem. Breadcrumb Rich Results לא יוצגו.

בעיה 2: סדר positions הפוך

עמוד הבית צריך להיות position 1 (ראשון), הדף הנוכחי אחרון. בכל הדפים הסדר הפוך — הדף הנוכחי הוא position 1 ועמוד הבית הוא אחרון.

בעיה 3: "item" חסר / עודף

לפי מפרט Google: הפריט האחרון (הדף הנוכחי) לא צריך "item" URL. כל שאר הפריטים חייבים "item" עם URL מלא.

דוגמה — תיקון נדרש (כל דף)

// ✅ BreadcrumbList תקין — דוגמה עבור /insurance-policies/leumit-silver-and-gold/ { "@context": "https://schema.org", "@type": "BreadcrumbList", "itemListElement": [ { "@type": "ListItem", "position": 1, "name": "עמוד הבית", "item": "https://www.leumit.co.il/" }, { "@type": "ListItem", "position": 2, "name": "הביטוחים שלך עם לאומית", "item": "https://www.leumit.co.il/insurance-policies/" }, { "@type": "ListItem", "position": 3, "name": "לאומית זהב/כסף" } ] }

הוראות תיקון למפתח

תיקון 1: החלפת "type" ב-"@type" (קריטי — כל ה-JSON-LD)

בכל מתודה שמרנדרת JSON-LD, להחליף "type" ב-"@type" על כל האובייקטים:

  • ListItem ב-BreadcrumbList
  • Question ו-Answer ב-FAQPage
  • כל רכיב אחר שמייצר JSON-LD
// Umbraco C# — דוגמה לתיקון: // לפני: new { type = "ListItem", position = i, name = item.Name } // אחרי: new { @type = "ListItem", position = i, name = item.Name } // ב-C# השתמשו ב-@ כדי לעשות escape ל-keyword
תיקון 2: הפיכת סדר BreadcrumbList (קריטי)

לשנות את הלוגיקה כך שעמוד הבית = position 1, הדף הנוכחי = position אחרון.

// C# Pseudo-code: var breadcrumbs = GetAncestors().Reverse().ToList(); // Homepage first breadcrumbs.Add(currentPage); // Current page last for (int i = 0; i < breadcrumbs.Count; i++) { var item = new { @type = "ListItem", position = i + 1, name = breadcrumbs[i].Name }; // Add "item" URL to all EXCEPT the last one if (i < breadcrumbs.Count - 1) { item.item = breadcrumbs[i].Url; } }
תיקון 3: מניעת FAQPage ריק (קריטי)

להוסיף תנאי בתבנית — לא לרנדר FAQPage schema אם mainEntity ריק.

@if (Model.FaqItems != null && Model.FaqItems.Any()) { <script type="application/ld+json"> { "@context": "https://schema.org", "@type": "FAQPage", "mainEntity": [ @foreach (var faq in Model.FaqItems) { // render Question + acceptedAnswer } ] } </script> }
תיקון 4: הוספת acceptedAnswer לכל Question (קריטי)

כל Question חייב להכיל acceptedAnswer. אם לרכיב אין תשובה — לא לכלול אותו ב-schema.

{ "@type": "Question", "name": "מה הטקסט של השאלה?", "acceptedAnswer": { "@type": "Answer", "text": "הטקסט של התשובה כאן." } }
תיקון 5: הסרת "name" מ-FAQPage (נמוך)

Google לא תומך בשדה name על FAQPage. להסיר אותו.

// לפני: {"@context":"https://schema.org","@type":"FAQPage","name":"FFFF","mainEntity":[...]} // אחרי: {"@context":"https://schema.org","@type":"FAQPage","mainEntity":[...]}
תיקון 6: הגבלת FAQ component לתוכן Q&A בלבד (תהליכי)

להוסיף הערה/ולידציה ב-Umbraco על רכיב ה-FAQ:

// הודעה לעורך תוכן ב-Umbraco: "רכיב זה מיועד לשאלות ותשובות בלבד. אין להשתמש בו עבור: טבלאות מחירים, רשימות מיקומים, תוכן כללי. עבור תוכן אקורדיון שאינו Q&A — השתמשו ברכיב האקורדיון הרגיל."

איך למצוא את כל הדפים הפגועים

שיטה 1: סריקת Screaming Frog
  1. סרקו את leumit.co.il ב-Screaming Frog
  2. Configuration → Custom Extraction → XPath: //script[@type='application/ld+json']
  3. סננו את הפלט לדפים שמכילים FAQPage
  4. סמנו דפים שבהם mainEntity ריק [] או שהתוכן אינו שאלות
שיטה 2: שאילתה ב-Umbraco
  1. חפשו את כל הדפים שמשתמשים ב-document type faqTextItem
  2. בדקו ידנית שכל דף מכיל תוכן Q&A אמיתי
  3. הסירו את רכיב ה-FAQ מדפים שאינם מכילים שאלות ותשובות
שיטה 3: Google Search Console
  1. GSC → Enhancements → FAQ
  2. בדקו דפים עם שגיאות (errors) או אזהרות (warnings)
  3. דפים עם "Missing field acceptedAnswer" או "Invalid type" = הבאגים שזוהו כאן

רשימת אימות אחרי תיקון

  • הריצו כל דף מתוקן דרך Google Rich Results Test
  • ודאו ש-FAQPage מופיע רק בדפים עם תוכן Q&A אמיתי
  • ודאו ש-mainEntity אינו ריק באף דף
  • ודאו שכל Question מכיל acceptedAnswer עם @type: Answer
  • ודאו שכל הפריטים משתמשים ב-"@type" (עם @) ולא "type"
  • ודאו ש-BreadcrumbList מתחיל בעמוד הבית (position 1) ומסתיים בדף הנוכחי (אחרון)
  • ודאו שהפריט האחרון ב-BreadcrumbList לא מכיל "item" URL
  • ודאו שאין כתובות localhost בשום schema בפרודקשן
  • בקשו revalidation ב-Google Search Console אחרי פריסה
