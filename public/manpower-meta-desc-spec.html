1 הבעיה
כל עמודי המשרות (/job/*) חסרים תיאור מטא לחלוטין.
שדה metaDesc ב-Yoast/WPGraphQL מחזיר מחרוזת ריקה ("") → Next.js לא מרנדר תגית <meta name="description"> → גוגל מייצר snippet אוטומטי מתוכן העמוד → אובדן 15-30% מה-CTR.
היקף: כל עמודי /job/* ללא יוצא מן הכלל (כולל משרות פעילות ומשרות שתוקפן פג).
למה ב-Next.js ולא ב-Yoast? עמודי המשרות נבנים דינמית מ-API — לכל משרה כותרת ומיקום שונים. ל-Yoast אין גישה לשדות האלה כדי לייצר תיאור דינמי. לכן הפתרון חייב להיות בשכבת ה-Next.js שבה נתוני המשרה כבר זמינים.

2 פורמט דינמי נדרש
דרוש/ה [JOB_TITLE] – משרה ב[LOCATION] | מנפאואר ישראל. הגישו מועמדות עכשיו.
כלל חובה: המילה "דרוש/ה" חייבת להופיע בתחילת כל תיאור מטא של משרה. זוהי דרישה קבועה — אין לשנות, להסיר או להחליף אותה. המילה "דרוש/ה" היא המילה הראשונה בכל מקרה (גם ב-fallback ללא מיקום).
שדה מקור הנתון דוגמה סטטוס
[JOB_TITLE] pageProps.job.title מנהל/ת חשבונות חובה
[LOCATION] pageProps.job.jobAreas.nodes[0].name השפלה חובה — עם fallback
הגבלת תווים: תיאור מטא חייב להיות עד 155 תווים. הפורמט הבסיסי (ללא ערכים דינמיים) תופס ~50 תווים, כך שנותר מקום רחב לכותרות ומיקומים.
3 מקור הנתונים — מבנה __NEXT_DATA__
כל נתוני המשרה כבר זמינים ב-pageProps.job שמגיע מה-SSR. אין צורך בקריאת API נוספת.
מבנה הנתונים הרלוונטי (מתוך pageProps.job):
pageProps.job = { code: "236844", // מזהה משרה title: "מנהל/ת חשבונות", // ← JOB_TITLE ★ jobAreas: { // ← LOCATION ★ nodes: [ { name: "השפלה" } // ← שם האזור כאן ] }, scope: "משרה מלאה", // היקף משרה domain: "פיננסים וכספים", // תחום מקצועי subProfession:"מנהח״ש", // תת-תחום experience: "נדרש ניסיון", // דרישת ניסיון description: "<p>חברה במודיעין...</p>" // תיאור HTML }
שימו לב — jobAreas הוא אובייקט מקונן, לא מחרוזת!
כדי לגשת לשם האזור יש להשתמש ב: job.jobAreas?.nodes?.[0]?.name
אם nodes מכיל יותר מאזור אחד — להשתמש רק בראשון ([0]).
דוגמאות ערכים: "השפלה", "חיפה והצפון", "מרכז", "תל אביב"
אין לשנות את תגית ה-<title> הקיימת. המימוש הזה מוסיף רק <meta name="description"> ו-<meta property="og:description">. תגית ה-title ("[שם המשרה] - Manpower") נשארת כפי שהיא.
4 מימוש — קוד
המימוש מתבצע בקומפוננטת עמוד המשרה (/job/[slug]). יש להוסיף את הלוגיקה שמייצרת את התיאור הדינמי ומזריקה אותו לתגית <Head>.
שלב 1: להוסיף את הפונקציה הבאה מעל הגדרת הקומפוננטה (מחוץ לה)
/** * Generate dynamic meta description for job pages. * Format: "דרוש/ה [TITLE] – משרה ב[LOCATION] | מנפאואר ישראל. הגישו מועמדות עכשיו." * Max length: 155 characters. */ function generateJobMetaDescription(job) { const title = job.title || ''; const location = job.jobAreas?.nodes?.[0]?.name || ''; if (!title) { return 'משרות חדשות במנפאואר ישראל. הגישו מועמדות עכשיו.'; } if (!location) { return `דרוש/ה ${title} | מנפאואר ישראל. הגישו מועמדות עכשיו.`; } // Full format let desc = `דרוש/ה ${title} – משרה ב${location} | מנפאואר ישראל. הגישו מועמדות עכשיו.`; // If over 155 chars, try shorter version without "משרה ב" if (desc.length > 155) { desc = `דרוש/ה ${title} – ${location} | מנפאואר ישראל. הגישו מועמדות עכשיו.`; } // Final safety: hard truncate at 155 if (desc.length > 155) { desc = desc.slice(0, 152) + '...'; } return desc; }
שלב 2: להוסיף לתוך ה-Head הקיים בקומפוננטה (לא להחליף!)
// Inside the existing JobPage component in /job/[slug]: const metaDescription = generateJobMetaDescription(job); // Add these 2 lines inside the existing <Head> block: <meta name="description" content={metaDescription} /> <meta property="og:description" content={metaDescription} />
שימו לב: מכיוון שהנתונים כבר מגיעים ב-SSR (דרך getServerSideProps / getStaticProps), התיאור הדינמי יהיה בתוך ה-HTML הראשוני שגוגל מקבל — ללא צורך ב-JavaScript בצד הלקוח.

7 היכן בקוד — מיקום הקובץ
מבנה פרויקט קובץ לעריכה פעולה

(או layout.js + generateMetadata)
הפונקציה מוגדרת באותו קובץ של הקומפוננטה. מכיוון שהנתונים כבר מגיעים ב-SSR, אין צורך בקריאת API נוספת — רק לחלץ את title ו-jobAreas.nodes[0].name מתוך ה-props הקיימים.

// app/job/[slug]/page.js export async function generateMetadata({ params }) { const job = await fetchJob(params.slug); return { description: generateJobMetaDescription(job), openGraph: { description: generateJobMetaDescription(job), }, }; }
