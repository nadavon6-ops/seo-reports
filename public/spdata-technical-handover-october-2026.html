הממצא (אומת ב-29.10.2026)

  • בקשות בשם GPTBot, ClaudeBot ו-CCBot מקבלות 403 מ-Cloudflare עצמו (תשובת text/plain בת 25 בייט, "Your request was blocked"). בקשות בשם Googlebot, Bingbot, OAI-SearchBot, ChatGPT-User ו-PerplexityBot מקבלות 200.
  • קובץ robots.txt המוגש מתחיל בבלוק BEGIN Cloudflare Managed content: שורת Content-Signal: search=yes,ai-train=no ו-Disallow: / לכ-30 סורקים, בהם GPTBot, ClaudeBot, CCBot, Google-Extended, meta-externalagent ו-Applebot-Extended. רק אחריו מופיעות ההנחיות של האתר, שמתירות לאותם סורקים במפורש. הקובץ סותר את עצמו, והחסימה בפועל נעשית ממילא בשכבת Cloudflare.

המשמעות: התוכן אינו נגיש לחלק ממנועי ה-AI שהלקוח רוצה להופיע בהם. זו גם בדיוק התוצאה שדוח אוקטובר הזהיר ממנה כתנאי מוקדם למעבר למצב Proxied.

מה לעשות
  1. החלטת הלקוח (מופיעה בדוח המשימות שאינן טכניות): האם לאפשר לסורקי AI לאסוף את התוכן. ההמלצה שלנו: לאפשר. זו הייתה הכוונה המפורשת בקובץ robots.txt של האתר, וזה הבסיס לנראות ב-ChatGPT, Claude, Perplexity ו-Gemini.
  2. אם מאפשרים: ב-Cloudflare לבחור את הדומיין spdata.co.il, להיכנס אל Security > Settings > Configure AI bot policies ולסמן Allow (do not block) בשורות Training, Search ו-Agent.
  3. באותו אזור (Security > Bots / AI Crawl Control) לכבות את האפשרות Managed robots.txt, כדי ש-Cloudflare יפסיק להוסיף בלוק משלו לקובץ. אם בלוק החסימה נשאר, לאתר כלל מותאם ב-Security rules ולהשבית אותו.
  4. בדיקה: curl -sI -A "GPTBot/1.2" https://www.spdata.co.il/ מחזיר 200, ו-curl -s https://www.spdata.co.il/robots.txt אינו מכיל את המחרוזת Cloudflare Managed content.
