1הסרת כפילות WebSiteתיקון

מה שגוי: בלוק WebSite נפלט פעמיים, זהה לחלוטין, בעמוד הבית.

מה לעשות: למחוק אחד משני הבלוקים. להשאיר את זה:

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "WebSite",
  "@id": "https://www.leumit.co.il#website",
  "name": "לאומית שירותי בריאות",
  "alternateName": "Leumit Health Services",
  "url": "https://www.leumit.co.il",
  "inLanguage": "he-IL",
  "publisher": { "@id": "https://www.leumit.co.il#organization" }
}
</script>
2הוספת יוטיוב ל-sameAsתיקון

מה חסר: ב-sameAs של הארגון מופיעים רק פייסבוק ואינסטגרם. ערוץ היוטיוב הרשמי חסר.

מה לעשות: להחליף את מערך ה-sameAs בשתי סכמות הארגון (Organization ו-MedicalOrganization) בעמוד הבית:

"sameAs": [
  "https://www.facebook.com/leumit",
  "https://www.instagram.com/leumit_healthcare/",
  "https://www.youtube.com/@LeumitHealthCare"
]

לינקדאין לא אומת כשייך ללאומית ולכן אינו נכלל. אם קיים עמוד חברה רשמי, יש להוסיפו.

{

  "@type": "JobPosting",
  "title": "{{job.title}}",
  "description": "{{job.fullDescriptionHtml}}",

  "employmentType": "{{job.employmentType}}",

    "@type": "Organization",
    "name": "לאומית שירותי בריאות",
    "sameAs": "https://www.leumit.co.il"
  },
  "jobLocation": {
    "@type": "Place",
    "address": {
      "@type": "PostalAddress",

דרישות חובה של גוגל: datePosted חייב להיות תאריך ISO 8601 (YYYY-MM-DD), לא טקסט חופשי. description חייב להכיל את תיאור המשרה המלא כפי שמוצג בעמוד (תיאור, דרישות, היקף), ומותר בו HTML. employmentType מקבל ערכים מוגדרים: FULL_TIME, PART_TIME, CONTRACTOR, TEMPORARY. ב-jobLocation יש למלא את המיקום הספציפי ביותר שקיים (עיר ורחוב); אזור רחב בלבד עלול להחליש את התוצאה. משרה שנסגרה: להסיר מהאתר, או להוסיף validThrough עם תאריך אמיתי.

8VideoObject (מותנה)חדש19 עמודים

מה חסר: ב-19 עמודים מוטמע סרטון יוטיוב בלי סכמה.

היכן: רכיב הווידאו. להטמיע רק כשקיים iframe של יוטיוב בעמוד. מזהה הסרטון נשלף מה-iframe.

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "VideoObject",
  "name": "{{video.title}}",
  "description": "{{video.description}}",
  "thumbnailUrl": "https://i.ytimg.com/vi/{{video.id}}/maxresdefault.jpg",
  "uploadDate": "{{video.uploadDate}}",
  "embedUrl": "https://www.youtube.com/embed/{{video.id}}"
}
</script>

דוגמה אמיתית: הסרטון "תזונה בגיל המעבר" (מזהה _p2LbovBQq0, הועלה ב-2026-06-17). אין להוסיף contentUrl עבור סרטוני יוטיוב. רשימת 19 העמודים בנספח.

שימו לב לתמונה הממוזערת: maxresdefault.jpg אינו קיים עבור כל סרטון ביוטיוב. יש לוודא שהקובץ מחזיר 200, ואם לא, ליפול חזרה ל-hqdefault.jpg (שקיים תמיד), או לשלוף את התמונה מ-YouTube Data API. uploadDate ו-name יש לשלוף מנתוני הסרטון, לא להמציא.

11MedicalClinic · Pharmacyחסום

הבעיה: איתור המרפאות ובתי המרקחת הוא אפליקציית צד לקוח. אין כתובת URL ייחודית לאף סניף. חמש הכתובות של מסך הפריט הבודד קיימות ב-sitemap ומחזירות 404 (ראו משימה 4).

המשמעות: סכמה היא תמיד ברמת עמוד. בלי עמוד סניף, אין לאן להטמיע. זהו גם פער SEO מקומי: לאומית לא מתחרה היום על חיפושים כמו "מרפאת לאומית [עיר]", כי אין עמוד שיכול לדרג.

התנאי המקדים: לבנות עמוד ייעודי לכל סניף, שעומד בארבעה תנאים:

1. כתובת URL קבועה וייחודית לכל סניף
2. רינדור בשרת (לא רינדור בצד לקוח בלבד)
3. קישור פנימי שניתן לסריקה מעמוד האיתור
4. תוכן גלוי אמיתי: שם, כתובת, טלפון, שעות פעילות, תחומי שירות

ואז ניתן להטמיע, כשהערכים נשלפים מרשומת הסניף. בעמודי בתי מרקחת יש להשתמש באותו מבנה בדיוק, אך עם "@type": "Pharmacy" במקום MedicalClinic:
