לאומית: בדיקת סכמות והשלמות לגרסה הבאה

מיפוי הסכמות הקיימות באתר לאומית מול מכבי וכללית, ורשימת התוספות המומלצות לפני עליית הגרסה החדשה.

אתר: leumit.co.il השוואה: maccabi4u.co.il · clalit.co.il בדיקה חיה: יולי 2026

האם חסר משהו שיש למכבי או לכללית?

לא. כל סוג סכמה שמוטמע אצל מכבי או כללית מוטמע גם אצל לאומית, ובחלק מהמקרים לאומית מרחיבה מעבר לכך. בבדיקה החיה לא נמצאה אף סכמה מהותית שקיימת אצל המתחרות ונעדרת מאתר לאומית.

הפער היחיד מול מכבי: ברשימת הפרופילים החברתיים (sameAs) מכבי כוללת גם יוטיוב ולינקדאין, בעוד לאומית כוללת כרגע פייסבוק ואינסטגרם בלבד. מומלץ להוסיף את ערוץ היוטיוב הרשמי של לאומית, @LeumitHealthCare, לרשימה. לינקדאין לא אומת כשייך ללאומית, ולכן יתווסף רק אם קיים עמוד חברה מאומת.
SearchAction: הרכיב היחיד הנוסף שקיים אצל מכבי ונעדר מלאומית. גוגל הוציאה אותו משימוש (תיבת החיפוש בקישורי האתר בוטלה), ולכן אין להטמיעו למרות שהוא מופיע אצל מכבי.

שדרוגים יזומים לשמירה על ההובלה

מאחר שאין פער מהותי מול המתחרות, אלו סוגי סכמה ייעודיים לתחום הבריאות שכדאי להוסיף כדי להרחיב את היתרון. אף אחת משלוש הקופות אינה מיישמת אותם כיום, כך שהטמעתם ממצבת את לאומית ראשונה גם ברובד הזה. כל פריט כולל היכן להטמיע, מדוע זה עוזר, וקוד JSON-LD מוכן עם נתונים אמיתיים.

1FAQPage: שאלות נפוצותROI גבוהFAQPage

היכן: עמודים עם שאלות ותשובות אמיתיות: זכויות, ביטוחים משלימים, שיניים, יצירת קשר, "תור ללא כרטיס".

אתרי בריאות רשמיים זכאים לתצוגות FAQ מועשרות בגוגל, בשונה מאתרים מסחריים. מומלץ לאשר את נוסח השאלות והתשובות מול הלקוח לפני ההטמעה.

קוד JSON-LD 
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "איך מזמינים תור ללא כרטיס מגנטי?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "ניתן לזמן תור דרך האזור האישי באתר או באפליקציה, וכן בטלפון *507 ללא צורך בסיסמה."
      }
    },
    {
      "@type": "Question",
      "name": "אילו תוכניות ביטוח משלים מציעה לאומית?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "לאומית מציעה שתי תוכניות ביטוח משלים, לאומית כסף ולאומית זהב, המרחיבות את הכיסוי הרפואי מעבר לסל הבריאות הבסיסי."
      }
    }
  ]
}
</script>
2MedicalWebPage: עמודי תוכן רפואיבידול מהמתחרותMedicalWebPage

היכן: ספריית התוכן הרפואי: התפתחות הילד, הריון, תזונה, בריאות הנפש, בריאות האישה. כרגע לעמודים אלו יש רק Breadcrumb + ארגון.

זהו סוג הסכמה הייעודי לתוכן רפואי, והוא מחזק את אותות ה-E-E-A-T ואת בהירות התוכן עבור מנועי החיפוש ומנועי ה-AI. אף אחת מהקופות אינה עושה זאת, ולכן זהו יתרון בידול ברור. אם קיים תאריך בדיקה רפואית ובעל מקצוע שאישר את התוכן, מומלץ להוסיף גם את השדות lastReviewed ו-reviewedBy.

קוד JSON-LD (עמוד ספקטרום האוטיזם) 
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "MedicalWebPage",
  "url": "https://www.leumit.co.il/child-development/the-autism-spectrum-in-children-identification-diagnosis-and-treatment/",
  "name": "הספקטרום האוטיסטי בילדים: זיהוי, אבחון וטיפול",
  "inLanguage": "he-IL",
  "publisher": { "@id": "https://www.leumit.co.il#organization" },
  "about": {
    "@type": "MedicalCondition",
    "name": "הספקטרום האוטיסטי",
    "alternateName": "Autism Spectrum Disorder"
  }
}
</script>
3MedicalClinic / Pharmacy: עמודי איתורחשיפה מקומיתMedicalClinic · Pharmacy

היכן: עמודי איתור מרפאות, בתי מרקחת, מרפאות שיניים ומוקדי חירום, וכן בעמודי הסניף הבודד.

הוספת geo ו-openingHours מחדדת למנועים את זהות הסניף כישות מקומית ותומכת בזכאות לתכונות מקומיות (ההופעה במפות ובחבילה המקומית מונעת בעיקר מ-Google Business Profile). מאחר שמדובר במאות סניפים, המבנה קבוע והערכים הספציפיים (כתובת, קואורדינטות, טלפון ושעות) נשלפים אוטומטית מרשומת הסניף במערכת הניהול לכל עמוד.

מבנה הסכמה (הערכים נשלפים לכל סניף) 
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "MedicalClinic",
  "name": "מרפאת לאומית, שם הסניף",
  "parentOrganization": { "@id": "https://www.leumit.co.il#organization" },
  "address": {
    "@type": "PostalAddress",
    "streetAddress": "רחוב ומספר",
    "addressLocality": "עיר",
    "addressCountry": "IL"
  },
  "geo": { "@type": "GeoCoordinates", "latitude": "קו רוחב", "longitude": "קו אורך" },
  "telephone": "*507",
  "openingHoursSpecification": [{
    "@type": "OpeningHoursSpecification",
    "dayOfWeek": ["Sunday","Monday","Tuesday","Wednesday","Thursday"],
    "opens": "08:00", "closes": "19:00"
  }]
}
</script>
4Physician: עמודי רופאיםמומלץPhysician

היכן: עמודי פרופיל רופא בתוצאות איתור הרופאים.

מזהה כל רופא כישות עם תחום התמחות ושיוך למרפאה, ותומך בהופעה עשירה ובזיהוי ישויות ב-AI. כמו בסניפים, המבנה קבוע והערכים (שם, תחום התמחות ושיוך) נשלפים אוטומטית מרשומת הרופא במערכת הניהול לכל עמוד.

מבנה הסכמה (הערכים נשלפים לכל רופא) 
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Physician",
  "name": "שם הרופא",
  "medicalSpecialty": "תחום ההתמחות",
  "memberOf": { "@id": "https://www.leumit.co.il#medical-organization" },
  "availableService": { "@type": "MedicalProcedure", "name": "סוג השירות" }
}
</script>
5NewsArticle: עמודי חדשותמומלץNewsArticle

היכן: עמודי חדשות ואירועים (למשל הזכייה במקום הראשון בסקר גלובס).

תומך בזכאות לתכונות הכתבה בתוצאות החיפוש (כותרת, תאריך ותמונה), במקומות שבהם גוגל בוחרת להציגן. גוגל דורשת publisher עם name ו-logo, ולכן הוא מפורט כאן במלואו ולא כהפניית @id בלבד. את השדות datePublished ו-dateModified יש לקשור לתאריכי הפרסום והעדכון האמיתיים של העמוד מתוך מערכת הניהול.

קוד JSON-LD (הכתבה על דירוג גלובס) 
<script type="application/ld+json">
{
  "@context": "https://schema.org",

  "image": ["https://www.leumit.co.il/media/xvwe2e2h/16.png"],

    "@type": "Organization",

    "logo": {
      "@type": "ImageObject",
      "url": "https://www.leumit.co.il/media/rwsdhs1u/36467_113985_leumit_website_bnrs_logo_208x52_05.png"
    }
  }
}
</script>
6Service / MedicalProcedure: עמודי שירותמומלץService

היכן: עמודי שירות ופוליסות ביטוח בודדים. כרגע Service מופיע רק מקונן בתוך makesOffer בעמוד הבית, ולא בעמודי השירות עצמם.

סכמת Service עצמאית בכל עמוד שירות מחדדת למנועים מה מוצע בעמוד הספציפי.

קוד JSON-LD 
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Service",
  "name": "ביטוח משלים לאומית",
  "serviceType": "ביטוח בריאות משלים",
  "provider": { "@id": "https://www.leumit.co.il#organization" },
  "areaServed": "IL"
}
</script>
7VideoObject: תוכן וידאוהיכן שרלוונטיVideoObject

היכן: רק בעמודים שיש בהם וידאו אמיתי (הסברים רפואיים, סרטוני מדריך).

מאפשר הופעה כתוצאת וידאו מועשרת. להטמיע רק כאשר קיים סרטון בעמוד. אם אין סרטון, אין להטמיע את הסכמה.

8HealthInsurancePlan: עמודי ביטוחמומלץHealthInsurancePlan · MedicalTest

היכן: עמודי הביטוח המשלים והפוליסות. סוג ייעודי ומדויק יותר מ-Service הכללי לתיאור תכניות ביטוח בריאות. בנוסף, MedicalTest לעמודי בדיקות ואבחונים, ו-Drug רק אם קיימים עמודי מידע על תרופות (למשל אישור תרופות).

מחדד למנועים שמדובר בתכנית ביטוח בריאות עם היקף כיסוי מוגדר, במקום שירות גנרי.

קוד JSON-LD 
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "HealthInsurancePlan",
  "name": "לאומית זהב",
  "alternateName": "ביטוח משלים לאומית",
  "provider": { "@id": "https://www.leumit.co.il#organization" }
}
</script>

כללי הטמעה

מיקום נכון: WebSite ו-Organization/MedicalOrganization מופיעות בעמוד הבית בלבד. כל שאר הסכמות (FAQPage, MedicalWebPage, Breadcrumb, Physician, Service וכו') הן פר-עמוד.

מבנה רזה: בכל עמוד פנימי להשתמש ב-@id שמפנה לישות הארגון והמפרסם בעמוד הבית, בלי לשכפל את כל פרטי הארגון. כך הסכמה נשארת קלה ומחוברת לישות אחת מרכזית.

לפני עלייה לאוויר יש לאמת כל בלוק מול דרישות התוצאות המועשרות של גוגל לכל סוג, ולוודא שהלוגו והתמונות אמיתיים ועומדים בדרישות המימדים.
