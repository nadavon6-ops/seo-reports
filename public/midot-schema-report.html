1. Duplicate Organization and WebSite nodes on the homepage
The problem: the homepage outputs three JSON-LD scripts. Yoast's graph declares #organization and #website. Two hand-coded scripts in the theme header declare the same two @id values again, with different content. Google merges nodes that share an @id, so it receives two conflicting descriptions of the same organization, including two different logos.
@idHand-coded script (header)Yoast graph
#organization@type ProfessionalService
logo /uploads/sites/8/2019/04/logo.png
alternateName "Midot Institute - Polygraph & Integrity Testing"		@type Organization
logo /uploads/sites/8/2024/12/logo.png (311×133)
alternateName "מכון מידות | בדיקות פוליגרף, מבחן אמינות, מבחני מיון לעבודה ועוד!"
#websitedescription "מכון מידות - מומחים בבדיקות פוליגרף, הערכות מהימנות ובדיקות יושרה לארגונים ופרטיים. מובילים בתחום בישראל"description "מכון מידות | בדיקות פוליגרף, מבחן אמינות, מבחני מיון לעבודה ועוד!"

What to do

  1. Delete both hand-coded scripts from the header: the block whose @type is ProfessionalService and the block whose @type is WebSite. Do not add a replacement: the WebSite node in Yoast's graph stays as it is.
  2. Move the business details into Yoast's Organization node (functionality plugin or functions.php). The phone and address below are the ones shown in the site footer: 
    <?php
// Homepage only: merge the business details into Yoast's Organization node.
add_filter( 'wpseo_schema_organization', function ( $data ) {
    if ( ! is_front_page() ) {
        return $data;
    }
    $data['@type']     = array( 'Organization', 'ProfessionalService' );
    $data['telephone'] = '+972-3-616-1111';
    $data['address']   = array(
        '@type'           => 'PostalAddress',
        'streetAddress'   => 'בר כוכבא 23, מגדלי V Tower',
        'addressLocality' => 'בני ברק',
        'addressCountry'  => 'IL',
    );
    $data['sameAs']    = array(
        'https://www.facebook.com/MidotEnsuringPersonnelIntegrity',
        'https://www.linkedin.com/company/midot-israel',
    );
    return $data;
} );
  3. In Yoast → Settings → Site representation, replace the tagline in the organization's alternate-name field with Midot, the short name used in the site footer ("© 2026 Midot").
  4. Do not carry over openingHours, priceRange or geo from the deleted block unless Midot confirms the values. None of them appears anywhere on the site.

Acceptance: the homepage has exactly one node per @id, one Organization and one WebSite.

Why Search Console shows the sitemaps as "Success"

The sitemap status only confirms that Google could read the sitemap file. It does not test the URLs listed in it. URL Inspection shows that Google has not crawled these pages yet: the conference URL tested is "Discovered – currently not indexed", and the others are "URL is unknown to Google". So no server-error report exists yet. Once Googlebot requests them, it will receive the 500.

Where the error is

A HEAD request to the same URLs returns 200, and a GET returns 500. WordPress answers HEAD requests before it loads the template, so the fatal error is raised while the template renders the page body: the single template of the conference post type (example: post ID 1963, /conference/integrity-in-the-world-of-work/) and the template used by page ID 1231.

What to do

  1. In wp-config.php set WP_DEBUG and WP_DEBUG_LOG to true and WP_DEBUG_DISPLAY to false, open one of the URLs above, then read wp-content/debug.log. The fatal error line names the file and line. The server runs PHP 8.4.
  2. Fix the template so all 59 URLs return 200 with their content.
  3. If single conference pages are not meant to be public, fix the error anyway, then set the Conferences content type to not appear in search results in Yoast → Settings → Content types. Yoast then drops conference-sitemap.xml from the sitemap index.

Acceptance: a GET request to every URL in the list returns 200.
