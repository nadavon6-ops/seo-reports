1. Exposed Google Cloud service-account key
The problem: a key file for the service account website@midot-website-1575970550589.iam.gserviceaccount.com (Google Cloud project midot-website-1575970550589, key ID starting 1c07522) was publicly downloadable from the theme folder. The file no longer loads, but a copy downloaded before that still works until the key is disabled in Google Cloud.

What to do

These steps need someone with admin rights on the Google Cloud project.

  1. Disable the key now. Disabling is reversible, so it can be re-enabled briefly if something turns out to depend on it.
  2. Check whether anything else on the site uses this service account (forms, scheduled tasks, other templates). If something does, create a new key with only the permissions it needs, store it outside the public web folder, and update the code.
  3. Delete the old key.
  4. Review the Cloud audit logs for any use of the key, and review the service account's roles and the files shared with it.
  5. Remove copies of the key file from backups, staging copies and code history.
  6. Move the google-api-php-client-2.2.4 library out of the public theme folder, or block the whole folder at the server level. The rest of the folder is still publicly reachable (for example composer.json).

Acceptance: the old key is deleted in Google Cloud, and the library folder no longer serves files to the public.

2. Empty page: /מטפלות-מתעללות/
The problem: midot.co.il/מטפלות-מתעללות/ (page ID 1231) reads its list from a Google Sheet that has been deleted. The page returns 200 with an empty results table ("לא נמצאו תוצאות"), is set to index, and is listed in page-sitemap.xml. Whether to restore the list is Midot's decision.

What to do

  1. Unpublish the page until Midot decides. It had no Google search impressions in the past 12 months and has no known backlinks or internal links.
  2. If Midot restores the list: the Sheet should be owned by a Midot account and shared read-only with the service account. When the Sheet cannot be read, the page should show a "temporarily unavailable" message instead of "no results" or a fatal error.

Acceptance: the page is unpublished and no longer listed in page-sitemap.xml, or it is restored with its list and the error handling above.
