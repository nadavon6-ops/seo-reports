1. Exposed Google Cloud service-account key
The problem: a key file for the service account website@midot-website-1575970550589.iam.gserviceaccount.com (Google Cloud project midot-website-1575970550589, key ID starting 1c07522) was publicly downloadable at wp-content/themes/midot-th/inc/google-api-php-client-2.2.4/credentials.json. The file no longer loads, but any copy downloaded before then can be used for as long as the key remains active in Google Cloud.

In Google Cloud (an admin of the project)

The development team does not have access to this project. Midot needs to identify who administers it, for example the developer or agency that set up the site's Google integration, or the owner of the Google account that created the project.

  1. Disable the key now. Disabling is reversible, so it can be re-enabled briefly if something on the site turns out to depend on it.
  2. Delete the old key once the site steps below confirm nothing depends on it, or once a replacement key is in place.
  3. Review the Cloud audit logs for any use of the key, and review the service account's roles and the files shared with it.

On the site (development team)

  1. Check whether any code still uses this service account (forms, scheduled tasks, other templates). If something does, it will need a new key from the project admin, stored outside the public web folder.
  2. Remove copies of the key file from backups, staging copies and code history.
  3. Move the library folder wp-content/themes/midot-th/inc/google-api-php-client-2.2.4/ out of the public theme folder, or block the whole folder at the server level. Its PHP files can still be run directly over the web (for example src/Google/Client.php and vendor/autoload.php return 200), and its other files can be downloaded (for example composer.json).

Acceptance: the old key is deleted in Google Cloud, and every file in the library folder, including the .php files, returns 403 or 404 when requested directly.

2. Schema code printed as visible text on a new post
The problem: on the post midot.co.il/בדיקת-מהימנות-לעובדים-האם-אפשר-לנהל-סי/, the FAQ code was pasted into the page's schema field without the <script type="application/ld+json"> wrapper. Visitors see the raw JSON printed on the page (in section.section-schema), and search engines get no FAQ schema. The code itself is valid and matches the page's 6 questions and answers. It is the only page on the site with this problem.

What to do

Replace the contents of that post's schema field with the block below: the same 6 questions and answers, wrapped in the script tag, in the same format as the 22 other pages that carry the block. Do not add it as a second block, or the raw text stays on the page. Google no longer shows FAQ rich results, so the value is consistency with the rest of the site and a machine-readable Q&A, not a search feature.
