משקל כבד
דסקטופ מהיר וסביר. סלולר איטי מאוד — תהליך טעינת JavaScript תופס את ה-Main Thread למעלה מ-7 שניות, ו-LCP חורג מהסף. הפוטנציאל לשיפור גדול ומבוסס על פעולות חד-משמעיות.

בעיות מרכזיות

  • Cloudflare Bot Detection (challenge-platform/jsd/main.js) — הסקריפט חוסם את ה-Main Thread כמעט 5 שניות בסלולר ו-1.3 שניות בדסקטופ. ~5,000ms
  • JavaScript מיותר בטעינה ראשונית — 575KB לא בשימוש בסלולר, 1,355KB בדסקטופ. נטענים chunks ספציפיים לעמודים כמו /my/dashboard/smartAgent, /employers/[slug] ו-/frequently-asked-questions על עמוד הבית. ~1,355KB
  • אוסף סקריפטים צד-שלישי טוענים מוקדם מדי — GTM-MM466BW + gtag G-X5YPSNW48L + AW-674976774 Google Ads, TikTok Pixel, Facebook Pixel, OneTrust CookieLaw, ווידג'ט נגישות acsbapp. כולם רצים לפני אירוע טעינה מלאה. ~750ms script
  • ווידג'ט נגישות acsbapp — 92KB שנטענים, 71KB לא בשימוש. טוען בראש הדף. 92KB
  • CLS 0.166 בדסקטופ — קפיצת layout מעל הסף של Core Web Vitals (0.1). יש לזהות באמצעות DevTools Performance את האלמנט שקופץ ולטפל בו. CLS 0.166
  • TTI גבוה במיוחד בסלולר — 14.2 שניות עד שהדף ריספונסיבי לחלוטין למשתמש.

מה לשפר

  • בטלו או הגבילו את Cloudflare Super Bot Fight Mode עבור עמודי תוכן ציבוריים. השאירו את ה-JS Challenge רק לעמודי טפסים רגישים (/contact, login, apply). זהו הרווח היחיד הכי גדול בדוח. −4,000ms
  • Code-splitting מבוסס-route עם dynamic() של Next.js — טעינו chunks של עמודים אחרים רק כשהמשתמש מנווט אליהם. בדקו ב-next/bundle-analyzer שה-Homepage bundle לא מכיל את smartAgent, employers, specializations. ~600KB
  • העבירו את כל תגי השיווק מאחורי Consent Mode v2 + deferred loading — GTM יטען ב-requestIdleCallback, ו-TikTok / Facebook Pixel רק לאחר LCP. פונקציונלית ללא שינוי, מבחינת ביצועים עשרות אחוזים שחרור Main Thread.
  • Lazy-load לווידג'ט הנגישות — טעינו את acsbapp רק לאחר אירוע load או באינטראקציה ראשונה, לא בראש הדף.
  • פתרו את ה-CLS בדסקטופ — קבעו width ו-height על תמונות hero ובאנרים מעל הקפל, וודאו ש-iframes/embeds מקבלים גודל שמור מראש. אתרו את האלמנט הקופץ דרך DevTools → Performance → Layout Shifts.
  • הוסיפו preconnect ל-cdn.cookielaw.org ו-www.googletagmanager.com כדי לקצר RTT לצד-שלישי שנשאר אחרי הדחייה.

משקל כבד
דסקטופ סביר ועם שולי שיפור. סלולר במצב קריטי — LCP חורג פי יותר מ-4 מהיעד של Google, ו-TBT כמעט 4 שניות. שני מקורות ראשיים לעיכוב: Cloudflare Bot Detection ו-HubSpot Analytics.

בעיות מרכזיות

  • Cloudflare Bot Detection (challenge-platform/jsd/main.js) — 4.75 שניות של Main Thread בסלולר, 1.3 שניות בדסקטופ. זהה ל-Manpower. ~4,750ms
  • HubSpot Analytics (js-eu1.hs-analytics.net) — 2.15 שניות של עיבוד בסלולר. טעינה סינכרונית מוקדם בדף. ~2,150ms
  • Next.js bundles עמוסים בטעינה ראשונית — בסלולר 557KB JS מבוזבז כולל 85KB מ-_app, 72KB מ-/our-services/[slug], ו-24KB מ-main. בדסקטופ 1,207KB מבוזבז כולל 142KB מ-/service/[slug], 111KB מ-/careers ו-74KB מ-/salary-calculator. 557KB / 1,207KB
  • ריבוי תגי Analytics וקונברסיות — GTM GTM-TMHMZBL, Google Ads AW-974622154, gtag G-3GJ0D5M8ZR — כולם לפני LCP.
  • ווידג'ט נגישות acsbapp — 217KB בסך הכל, 114KB לא בשימוש, טעון בראש הדף. 114KB
  • Redirect בטעינה ראשונית — מבזבז 1,050ms בסלולר ו-510ms בדסקטופ לפני שה-HTML מתחיל להגיע. 1,050ms
  • LCP 10.4s בסלולר — המשתמש רואה את הפריט הראשי רק אחרי 10 שניות. חורג פי 4+ מהיעד.

מה לשפר

  • בטלו את Cloudflare JS Challenge בעמודי תוכן ציבוריים. השאירו אותו רק באזורי הרשמה/קורות-חיים. זה לבדו יוריד ~4 שניות ב-LCP ו-Main Thread בסלולר. −4,000ms
  • העבירו את HubSpot Tracking Code ל-async טעינה לאחר LCP. ניתן לעשות זאת דרך HubSpot's sendEvent בצד לקוח + טעינה עצלה של hs-analytics.js דרך IntersectionObserver או requestIdleCallback. −2,000ms
  • Route-based code-splitting עם next/dynamic — חובה לוודא שה-Homepage bundle לא מכיל את service/[slug], careers, our-services/[slug]. הריצו next build --profile וניתוח bundle. ~500KB
  • איחוד ודחייה של תגי שיווק — GTM + Google Ads + Meta Pixel ייטענו כולם דרך GTM ב-requestIdleCallback לאחר אירוע LCP, עם Consent Mode v2.
  • Lazy-load לווידג'ט acsbapp — טעינה רק באינטראקציה ראשונה או לאחר load. 114KB שלא בשימוש חוסכים מ-Main Thread.
  • Preload ל-LCP element — זהו את התמונה/הטקסט הראשון מעל הקפל והוסיפו <link rel="preload" as="image"> עם fetchpriority="high".
  • בטלו את ה-redirect בטעינה ראשונית — הפנו ישירות לכתובת הקנונית (https://experis.co.il/) כדי לחסוך עד 1,050ms בסלולר. −1,050ms
