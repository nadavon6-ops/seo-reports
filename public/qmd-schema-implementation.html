Schema Implementation

Every structured data block to be added to qmd.net, with the exact code, where it goes, and what each one does and does not produce in Google Search. Built from the site as it renders today and validated against Google's current requirements.

For the development team  ·  Prepared 16 August 2026  ·  Platform WordPress, Elementor, Yoast SEO, WP Rocket

01 Install the schema pluginstart here

Every block in this report is delivered through one file. Google accepts structured data in several separate script blocks, so a second <script type="application/ld+json"> is not invalid in itself. The reason everything here goes into the graph Yoast already outputs is different, and it matters: every node below refers to the company by @id, and the company node belongs to Yoast. Add a second one and the site describes QMD twice, in two places that will drift apart the first time someone edits a setting. Extending the existing graph keeps one company, one set of references, one thing to maintain.

Where it goesUpload the file as wp-content/mu-plugins/qmd-schema.php. Create the mu-plugins folder if it does not exist. Files there load automatically, need no activation, and survive theme and plugin updates. Not the theme functions.php, not the footer, not an Elementor HTML widget, not Tag Manager.

  1. Fill in the values listed in section 11. Leave out anything QMD cannot confirm.
  2. Upload qmd-schema.php to wp-content/mu-plugins/.
  3. Purge the WP Rocket cache. Nothing changes in the served HTML until you do.
  4. Load any page, view source, and confirm there is still exactly one JSON-LD script.

The complete file is in section 12. Sections 2 to 10 show the JSON-LD each part of it produces, so the output can be reviewed before it goes live.

02 Organization

The Organization node already exists and carries five properties: @id, name, url, logo and image. Its name is currently the site title, QMD: Silicone & Polyisoprene Elastomer Manufacturer, which is a page title rather than a company name. Every other node in the graph points at this one by @id, so it is the first thing to correct.

One breadcrumb correction, homepage only

Google’s requirement is to define a BreadcrumbList that contains at least two ListItems. The homepage emits exactly one, Home, so it cannot meet that and is not valid breadcrumb markup. It is suppressed on the homepage only. Every other page keeps the breadcrumb it already has, and those are correct.

add_filter( 'wpseo_schema_needs_breadcrumb', function ( $needed ) {
	return ( '/' === qmd_schema_path() ) ? false : $needed;
} );
What this produces
  • Correct company name in Google's entity understanding, replacing the site title.
  • Four verified company addresses, ten named facilities and six named sales contacts attached to the company.
  • Knowledge panel eligibility signals. The logo is already 931 by 229 pixels, which clears Google's 112 pixel minimum on both sides.
  • knowsAbout states the manufacturing competencies and the six clinical areas the site covers, once, on the company.
What it does not produce
  • No rich result of its own. Organization data feeds entity understanding and the knowledge panel, neither of which is a SERP feature you can trigger on demand.
  • knowsAbout and location are schema.org properties that Google does not list under Organization. They are kept because they are accurate, not because they earn a feature.
03 Facility addresses and places

Ten facilities are listed on the locations page across six countries: United States, Germany, France, Slovakia, Israel and India. Arthesys S.R.O. and Biometrix S.R.O. are two separate entries that share one address in Samorin, Slovakia.

All ten become Place objects under location, each carrying the facility name and its own phone number, neither of which a PostalAddress can hold.

Only four of them are also asserted as addresses of QMD under address: the global headquarters, the US customer service office, the European customer service center and the Shomrat site. Those are the four the page presents under QMD’s own name. The other six are separately named companies, Arthesys S.A and S.R.O., Biometrix S.R.O. and Ltd, Degania Silicone Ltd and Degania Medical Devices Pvt. Ltd, and the site never states how they relate to QMD corporately. Listing a subsidiary’s registered address as the parent company’s own address would assert a corporate structure nobody has confirmed, so those six keep their identity as named places instead. Once QMD confirms the ownership relationships they can be promoted to subOrganization.

05 Page types

Three pages are currently typed as a generic WebPage when a more specific type applies. Changing the type does not add a node, it refines the one already there, so the @id and every existing relationship stay intact.

PageNowChange to
/about/WebPageAboutPage
/contact/WebPageContactPage
/qmd-leadership/WebPageCollectionPage

Where it goesThe wpseo_schema_webpage filter, matched on the request path.

What this produces
  • A clearer statement of what each page is, which is what the page-type vocabulary exists for.
What it does not produce
  • No rich result. AboutPage, ContactPage and CollectionPage are descriptive types, not SERP features.
06 Leadership profiles12 pages

11 Values QMD needs to supplyaction needed

These eight properties belong on the Organization node but have no source anywhere on the site, so they are not in the code. Add the ones QMD can confirm and leave out the rest. An absent property is correct. A guessed one is not, and Google's guidelines require structured data to reflect what is genuinely true of the page and the business.

PropertyWhat is needed
legalNameThe registered company name, if it differs from QMD.
alternateNameAny name the company is also known by. Leave out if QMD is the only one.
sameAsThe official LinkedIn company page, and any other profile QMD owns. The site links to no social profile anywhere, so there is nothing to verify this against. One candidate exists but it must be confirmed by QMD before it goes in, because an unverified profile URL asserts an identity that may not be theirs.
foundingDateYear the company was founded, as YYYY or YYYY-MM-DD.
numberOfEmployeesA number or a range.
naicsNAICS industry code.
dunsDun and Bradstreet number.
vatIDVAT identification number.

None of these is required. Google states plainly that Organization has no required properties, so the markup is valid and useful without them.

function qmd_schema_path() {
	$uri  = isset( $_SERVER['REQUEST_URI'] ) ? wp_unslash( $_SERVER['REQUEST_URI'] ) : '/';
	$path = wp_parse_url( $uri, PHP_URL_PATH );
	if ( ! $path ) {
		$path = '/';
	}
	return trailingslashit( $path );
}

/**
 * 1. Enrich the Organization node Yoast already owns.
 *    The @id, url, logo and image are left exactly as Yoast emits them, so every
 *    existing reference in the graph keeps resolving.
 */
add_filter( 'wpseo_schema_organization', function ( $data ) {
	return array_merge( $data, qmd_schema_organization_data() );
} );

/**
 * 2. Refine the WebPage @type and attach mainEntity where the page is genuinely
 *    an about page, a contact page, a person profile or a collection.
 */
add_filter( 'wpseo_schema_webpage', function ( $data ) {
	$path  = qmd_schema_path();
	$types = qmd_schema_page_types();
	$mains = qmd_schema_main_entities();

	if ( isset( $types[ $path ] ) ) {
		$data['@type'] = $types[ $path ];
	}
	if ( isset( $mains[ $path ] ) ) {
		$data['mainEntity'] = array( '@id' => $mains[ $path ] );
	}
	return $data;
} );

/**
 * 3. Append the Person, ItemList, Product and OfferCatalog nodes to the graph.
 *    Nothing is printed separately -- these become part of Yoast's single @graph.
 */
add_filter( 'wpseo_schema_graph', function ( $graph ) {
	$path  = qmd_schema_path();
	$nodes = qmd_schema_nodes();

	if ( ! empty( $nodes[ $path ] ) ) {
		foreach ( $nodes[ $path ] as $node ) {
			$graph[] = $node;
		}
	}
	return $graph;
} );

/**
 * 4. Suppress the homepage breadcrumb.
 *    Google requires a BreadcrumbList to contain at least two ListItems. On the
 *    homepage Yoast emits exactly one ("Home"), which cannot qualify. Every other
 *    page keeps its breadcrumb untouched.
 */
add_filter( 'wpseo_schema_needs_breadcrumb', function ( $needed ) {
	return ( '/' === qmd_schema_path() ) ? false : $needed;
} );

13 Checks after deployment
  1. Purge the WP Rocket cache, then load a product page and view source. There must still be exactly one <script type="application/ld+json">. If there are two, the file was installed as a plugin that prints its own block rather than through the filters.
  2. Run the Schema Markup Validator at validator.schema.org on one page of each kind: the homepage, a leadership profile, a product page, a brand page, the capabilities page. Every block in this report returns zero errors there.
  3. Run the Rich Results Test on a leadership profile. It should detect Profile page.
  4. Run the Rich Results Test on a product page. It will report the product item as ineligible. That is expected, see section 8.
  5. In Search Console, use URL Inspection on the homepage and a leadership profile, then request indexing. Detection can take a few weeks to appear in the enhancement reports.

The breadcrumbs Yoast generates on inner pages are correct and four levels deep on product pages. They are not touched. The homepage is the one exception, covered in section 2.
